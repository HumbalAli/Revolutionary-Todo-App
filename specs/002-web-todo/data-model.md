# Data Model: Phase II - Full-Stack Web Todo App

## Task Entity

**Description**: Represents a todo item with core attributes and relationships

**Fields**:
- `id` (Integer, Primary Key, Auto-increment)
  - Unique identifier for each task
  - Auto-generated by the database
- `title` (String, Required, Max 255 characters)
  - Task title/description (required field)
  - Cannot be empty or null
- `description` (String, Optional, Max 1000 characters)
  - Detailed description of the task (optional)
  - Can be empty or null
- `completed` (Boolean, Default: false)
  - Completion status of the task
  - True if completed, False if pending
- `user_id` (Integer, Foreign Key, Required)
  - References the user who owns this task
  - Used for data isolation between users
- `created_at` (DateTime, Auto-generated)
  - Timestamp when the task was created
  - Auto-set by the database
- `updated_at` (DateTime, Auto-generated)
  - Timestamp when the task was last updated
  - Auto-updated by the database

**Validation Rules**:
- Title must be between 1-255 characters
- Title cannot be empty or contain only whitespace
- Description, if provided, must be 1000 characters or less
- User ID must reference an existing user
- Task cannot be modified by users other than the owner

**State Transitions**:
- `pending` (completed = false) → `completed` (completed = true) when user marks task complete
- `completed` (completed = true) → `pending` (completed = false) when user marks task incomplete

## User Entity

**Description**: Represents an authenticated user with associated tasks

**Fields**:
- `id` (Integer, Primary Key, Auto-increment)
  - Unique identifier for each user
  - Auto-generated by the database
- `email` (String, Required, Unique, Max 255 characters)
  - User's email address for authentication
  - Must be unique across all users
- `name` (String, Required, Max 255 characters)
  - User's display name
  - Cannot be empty
- `created_at` (DateTime, Auto-generated)
  - Timestamp when the user account was created
  - Auto-set by the database
- `updated_at` (DateTime, Auto-generated)
  - Timestamp when the user account was last updated
  - Auto-updated by the database

**Validation Rules**:
- Email must be a valid email format
- Email must be unique across all users
- Name must be between 1-255 characters
- Name cannot be empty or contain only whitespace

## Relationships

**User → Task (One-to-Many)**:
- One user can own many tasks
- Each task belongs to exactly one user
- Tasks are filtered by user ID for data isolation
- When a user is deleted, their tasks should also be deleted (cascade delete)

## Constraints

- All timestamps use UTC timezone
- Soft deletes are not implemented (hard deletes for tasks)
- Task titles must be unique per user (no duplicate titles for same user)
- Maximum 1000 tasks per user (enforced by application logic)
